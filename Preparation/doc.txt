Q- What is an event loop?(while answers include macro and micro queue both).
    Event loop is a JavaScript runtime mechanism that enables asynchronous programming by constantly monitoring the call stack
    and task queues, allowing the single-threaded engine to handle tasks without blocking the main thread. It executes synchronous 
    code first, then fully processes all tasks in the microtask queue (high priority, e.g., Promises) before handling one macrotask
    (e.g., setTimeout).

Q- Promise.all vs .race vs .any
    .all - Waits for all to succeed. If any one fails, it immediately rejects.
    .allSettled - Waits for all to finish, regardless of success or failure. (never rejects, always give outcome)
    .race - Returns the result of whichever promise finishes first (resolve or reject).
    .any - Returns the first one that succeeds. Ignores rejections unless all fail

Q- useTransition and useDeferredValue
    Both useTransition and useDeferredValue are React 18 concurrent features that mark updates as non-urgent so React can 
    prioritize user interactions over expensive renders. The difference is where control lives. useTransition wraps the state 
    setter — use it when you own the state and want an isPending flag to show explicit loading UI. useDeferredValue wraps the 
    value — use it when the value comes from props or an external source you can't control, and you want to keep showing stale
    content while the expensive render catches up. A key detail with useDeferredValue is that it does nothing without useMemo — 
    you have to memoize the expensive computation against the deferred value, otherwise the expensive work still runs on every 
    render. In practice I use useTransition for navigation and filter interactions where I control state, and useDeferredValue 
    in child components that receive props from parents and need to defer expensive rendering independently.
